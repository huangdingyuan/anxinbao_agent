# 安心保平台 · 项目设计文档

> 版本：v1.1 ｜ 更新日期：2026-11-25
> 说明：本文档基于当前代码库（`backend/`、`frontend/`、`deploy/`）实际实现整理。v1.1 变更：智能问答重构为 LangChain/LangGraph 保险顾问 Agent（StateGraph + Postgres Checkpointer），RAG 知识库以 LangChain BaseRetriever 封装。

---

## 1. 项目概述

「安心保」是一个面向 C 端用户的**保险商城 + AI 智能顾问**平台，核心能力：

- **产品浏览与投保**：在售保险产品（医疗险 / 重疾险 / 意外险 / 寿险）的展示、详情与投保入口。
- **AI 智能顾问（安安）**：基于 LangGraph Agent + RAG 的流式问答，结合产品库、条款知识库、费率表回答保险咨询，并能生成保障方案。
- **保障方案（Human-in-the-loop）**：推荐多款产品时通过 SSE `interrupt` 事件下发方案，等待用户确认后保存。
- **保单与理赔**：保单列表 / 详情 / 保障权益查询，理赔报案、状态跟踪。
- **知识库管理**：保险条款、费率表 PDF 的解析、切块、向量化入库与混合检索。

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 18 + TypeScript + Vite 6 + Ant Design 5 |
| 后端 | Python 3.14 + FastAPI + SQLAlchemy 2（asyncio）+ Uvicorn |
| Agent 框架 | LangGraph 1.x（StateGraph 确定性 RAG 流水线 + AsyncPostgresSaver Checkpointer） |
| LLM | DeepSeek（`langchain-deepseek` ChatDeepSeek 流式；legacy 回退路径为 OpenAI 兼容接口直连） |
| RAG 抽象 | LangChain 1.x BaseRetriever（条款 / 费率表 / 产品三路封装） |
| 向量模型 | sentence-transformers 本地模型 `BAAI/bge-small-zh-v1.5`（CPU，可降级） |
| 向量库 | Milvus 3（standalone，docker-compose 部署，Attu 可视化） |
| 业务库 | PostgreSQL 16（asyncpg 驱动；另有 psycopg 供 LangGraph checkpointer 使用） |
| 密码 | bcrypt（`pwdlib[argon2]` 依赖中实际使用 bcrypt） |
| 文档解析 | MinerU（`mineru-open-sdk`）+ pypdf，解析产物为 JSON |
| 包管理 | uv（backend）/ npm（frontend） |
| 部署 | Docker Compose（基础设施）+ Nginx（前端静态资源与 API 反代） |

## 6. 模块设计与 API 一览

### 6.1 user（认证与用户）
- `POST /api/v1/auth/login`：用户名 + 密码登录（bcrypt 校验），成功签发 JWT 访问令牌并返回用户资料（`{access_token, token_type, user}`）。
- `GET /api/v1/users/me`、`PATCH /api/v1/users/me`：查询 / 编辑个人资料（昵称、邮箱、手机号）。
- **身份传递**：登录成功后前端保存 JWT 访问令牌，后续请求携带 `Authorization: Bearer <token>` 请求头，由 `get_current_user_id` 依赖解析（HS256 签名，`JWT_SECRET_KEY` 配置密钥，默认有效期 7 天，可经 `JWT_EXPIRE_MINUTES` 调整）。

### 6.2 products（产品）
- `GET /api/v1/products`：在售产品列表（`status=active`），字段含名称、条款名、分类、保司、保费区间、亮点等。
- 分类约束：`medical | critical_illness | accident | life`。

### 6.3 policy（保单）
- `GET /api/v1/policies`、`GET /api/v1/policies/{id}`、`GET /api/v1/policies/{id}/benefits`：保单列表 / 详情 / 保障权益。

### 6.4 claim（理赔）
- `GET /api/v1/claims`、`POST /api/v1/claims`（报案）、`GET /api/v1/claims/{id}`、`PATCH /api/v1/claims/{id}/status`（状态流转）。

### 6.5 conversation（会话管理）
- `POST/GET /api/v1/chat-threads`、`PATCH/DELETE /api/v1/chat-threads/{thread_id}`：会话的增删改查；`thread_id`（UUID）同时作为 LangGraph Checkpointer 的 thread 标识，保存每轮图状态。

### 6.6 chat（智能问答，核心 —— LangGraph Agent）
- **Agent 图**（`chat/agent.py`，确定性 RAG 流水线，非 ReAct）：

  ```
  START → route(纯规则问题分类，零 LLM) ─┬─(tasks 非空)→ retrieve(三路并行检索) → generate(ChatDeepSeek 流式) → END
                                          └─(闲聊 tasks=[])────────────────────→ generate
  ```
  - `route`：`parse_rate_query` 命中 → rate（三路全开）；险种关键词 → product；条款信号词 → clause；寒暄 → general（跳过检索）；其余保守开产品+条款。
  - `retrieve`：调 `rag.gather_references` 并行检索，费率行优先、按 文档+页码 去重，产出候选产品（payload dict）、条款引用与 `build_context_block` 上下文。
  - `generate`：`SystemMessage(SYSTEM_PROMPT + 检索上下文) + 最近 10 条历史 + 当前问题`，`ChatDeepSeek.astream` 逐 token 生成。
  - `AdvisorState` 通道全部 JSON-safe（产品存 payload dict 而非 ORM），可被 Postgres checkpointer 序列化。
- **LangGraph 运行时**（`core/agent_runtime.py`）：lifespan 启动时建 psycopg `AsyncConnectionPool`（`autocommit=True, prepare_threshold=0`）→ `AsyncPostgresSaver.setup()` 幂等建 checkpoint 表 → 编译图单例；`thread_id = chat_threads.id`。初始化失败或 `CHAT_AGENT_ENABLED=false` 时图单例为 None，service 自动回退 legacy 直连路径，前端零感知。
- **SSE 接口**：`POST /api/v1/chat`（前端契约）与 `POST /api/v1/chat-threads/{thread_id}/chat`（内部）。service 以 `graph.astream(stream_mode=["messages","updates"])` 消费：generate 节点 token → `delta`/`message`；结束后 `filter_mentioned` 筛实际提及产品 → `references`/`additional_info` + 方案 `interrupt`；每轮输入显式重置全部状态通道，防止 checkpoint 继承上一轮检索结果。
  - `thread_id` 为空时自动创建会话（标题取首条消息前 20 字）。
  - `decision=approve/reject` 走 `handle_decision`（service 层，无 LLM），完成方案保存的确认闭环。
- `GET /api/v1/chat-threads/{thread_id}/messages`：历史消息 + 待确认 interrupt（`chat_messages` 仍为前端历史唯一数据源，与 checkpointer 双轨）。
- **RAG 封装**（`chat/rag.py`，LangChain BaseRetriever）：
  1. `ClauseRetriever`：包 `KnowledgeService.search` 混合检索（语义向量 + 关键词 + RRF）。
  2. `RateTableRetriever`：识别「年龄+性别+交费期」等维度后正则捞取费率原表行，附列说明（每千元保额保费、次标体加费、趸/季/月交折算）交给模型算费。
  3. `ProductRetriever`：问题 bigram 与产品名/描述/分类打分（阈值 `MIN_SCORE=2`，最多 8 款候选）。
  4. 三者另有 `@tool` 包装，预留未来升级 ReAct 的入口；底层实现仍在 `retrieval.py`，各自独立容错、失败降级。
  5. **回答后校验**：`filter_mentioned` 从回答中筛出实际提及的产品用于卡片展示（最长公共片段 ≥4 字，兼容简称）。
- **提示词设计**：系统人设「安安」，约束不夸大收益、以条款原文为准、命中费率行必须给出具体保费数值、最近 10 条历史作为上下文窗口。

### 6.7 insurance_plan（保障方案）
- `GET /api/v1/insurance-plans/{plan_id}`、`PATCH /api/v1/insurance-plans/{plan_id}/items/{item_id}/insured`（更换被保人）。
- 方案由对话推荐触发，经 `interrupt` → 用户确认（approve）后落库，与前端乐观渲染文案保持一致。

### 6.8 knowledge（知识库）
- `GET /api/v1/knowledge/documents`、`GET /documents/{id}/chunks`：文档与切块管理。
- `GET /api/v1/knowledge/search?q=`：混合检索调试接口。
- `POST /api/v1/knowledge/ingest`：从 `data/knowledge/` 解析产物批量入库（幂等，重建切块）。
- **入库流水线**：
  `条款/费率表 PDF → scripts/parse_kb.py（MinerU 解析 → data/knowledge/{kb|rate_table}/*.json）→ ingest_from_parsed_dir（标题层级切块 → kb_documents/kb_chunks）→ scripts/sync_milvus.py（bge 向量 → Milvus kb_chunks collection）`。

## 7. 数据模型

PostgreSQL 业务表（SQLAlchemy 模型 + `deploy/postgres/init` 初始化脚本）：

| 表 | 模块 | 要点 |
|---|---|---|
| `users` | user | 用户名/邮箱唯一，`password_hash`（bcrypt） |
| `products` | products | 分类 CHECK 约束，`highlights TEXT[]`，保费区间 |
| `policies` | policy | 保单主表 |
| `claims` | claim | 理赔单（仅 `updated_at` 混入） |
| `insurance_plans` / `insurance_plan_items` | insurance_plan | 方案主表 + 明细项 |
| `chat_threads` | conversation | UUID 主键 = LangGraph thread_id；`(user_id, updated_at DESC)` 索引 |
| `chat_messages` | chat | 消息持久化（前端历史接口数据源；图状态另由 LangGraph Checkpointer 保存，双轨） |
| `kb_documents` / `kb_chunks` | knowledge | 条款文档与切块（父块内容、标题路径） |
| `rate_table_files` / `rate_plans` | 费率（SQL 初始化） | 费率文件解析状态机：pending→parsed→validated→active/failed |
| `parent_chunks` | 智能体侧（SQL 初始化） | 父知识块，用于完整上下文与引用展示 |
| `checkpoints` / `checkpoint_blobs` / `checkpoint_writes` / `checkpoint_migrations` | LangGraph | Postgres Checkpointer 会话状态，由 `AsyncPostgresSaver.setup()` 启动时幂等自动建表（勿手写 DDL，版本化迁移由 saver 管理） |

公共约定：所有模型继承 `app/common/models.py` 的 `Base`，时间戳由 `CreateAtMixin` / `UpdateAtMixin` 提供（数据库端 `NOW()` 生成，UPDATE 自动刷新）。

## 9. 横切设计

- **异常与响应**：`core/exceptions.py` 注册全局处理器，`BizError`/`NotFoundError` 统一转 JSON 错误体；SSE 场景在流开始前抛错仍返回普通 JSON。
- **日志**：structlog 统一配置（`core/logging.py`），级别由 `LOGGING_LEVEL` 控制。
- **数据库会话**：每请求一个 `AsyncSession`（`common/deps.get_session`），写操作使用 `session.begin()` 事务。
- **流式与网关**：SSE 响应带 `X-Accel-Buffering: no` 禁用 Nginx 缓冲，保证逐段下发。
- **降级策略**：Embedding 模型加载失败 → 纯关键词检索；Milvus 不可用 / 知识库检索失败 → 无条款参考继续问答；产品检索失败 → 仅 LLM 通识回答；LangGraph 运行时初始化失败或 `CHAT_AGENT_ENABLED=false` → 问答自动回退 legacy 直连 LLM 路径（原 AsyncOpenAI 实现保留）。
- **事件循环**：Windows 上 psycopg 异步模式要求 Selector 事件循环，`app/main.py` 入口在 win32 下以 `asyncio.run(loop_factory=SelectorEventLoop)` 驱动 Uvicorn（Python 3.14 已弃用事件循环 policy）；Linux/Docker 无此处理。

## 11. 已知取舍与后续演进

- `chat` 与 `conversation` 共用 `/api/v1/chat-threads` 前缀，按职责拆分模块，边界清晰。
- 费率表解析依赖 MinerU 产物质量，`rate_table_files` 状态机为后续自动化校验/激活预留。
- 保单/理赔数据目前以演示数据为主，接入真实核心系统时需补充渠道与幂等设计。
- Agent 选确定性流水线而非 ReAct：费率精确行、RRF 融合等检索规则已针对回归行为调优，交给模型决定工具调用会引入漏调风险且破坏 SSE「逐字流 + 回答后一次性引用」时序；`rag.py` 已提供 `@tool` 包装，未来可平滑升级工具调用形态。
- 向量库保留 pymilvus 直连而非 `langchain-milvus`：现有 collection 为独立标量列 schema，且关键词路在 Postgres、RRF 融合与降级策略为自定义逻辑，标准 VectorStore 接口覆盖不了；BaseRetriever 封装已提供统一抽象。
- Checkpointer 与 `chat_messages` 双轨：前者保存每轮图状态（跨轮记忆、原生 interrupt 演进基础），后者仍是前端历史接口唯一数据源；每轮 prompt 历史由 service 注入 state，避免双记忆漂移。
